# 知識庫以代稱儲存，真名只存在加密的對照表

會議內容會送往外部 LLM 與 embedding 服務，也存在自架主機的 DB 與備份中。我們決定在本機偵測敏感內容（Presidio 偵測個資、secretlint 偵測密鑰），並在進入任何外部服務與資料表之前，把每個敏感值替換成全知識庫一致的代稱（同一真名永遠對應同一代稱，查詢也先做同樣替換，檢索才查得到）；事實、chunk 與 embedding 都只含代稱，真名只存在以 AES-256-GCM 逐列加密的對照表，顯示給已驗證的成員前才回填。密鑰類內容不做代稱，直接拒絕寫入。

## Considered Options

- **DB 存真名，只在送往 LLM 前去識別、回來時回填**：拒絕；實作簡單，但 DB 與 `pg_dump` 備份中所有敏感內容都是明文，「加密」只保護了一張無用的對照表。

## Consequences

- 加密金鑰只放在主機的 `.env`（權限 600），不進 DB，也不與 DB 備份放在一起；另存一份於密碼管理器。金鑰遺失，所有敏感值永久無法回填。
- 偵測不完美（中文口語人名常漏），以成員維護的敏感詞與排除詞清單補強；清單外的新人名可能外洩，為已知風險。
- 串流回答時代稱可能被切在兩個 chunk 之間，回填前需要緩衝。
- 訪客的試用工作區只含虛構示範資料，不做去識別。
