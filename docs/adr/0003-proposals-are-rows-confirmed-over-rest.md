# 提案是 DB 中的一等資料，確認只經由 REST，不經 LLM

任何會改動知識庫的意圖（輸入或修正），agent 只能建立提案；提案存成資料表，確認或拒絕由成員按鈕呼叫 REST endpoint 完成，agent 與 LLM 都沒有寫入知識庫的路徑。我們選這個而不是 LangGraph `interrupt`，因為提案需要被列出、晚點才確認、由其他成員確認、在確認當下重新比對衝突，以及被相關的新提案自動過期；更重要的是，上傳檔案中的 prompt injection 無法觸發寫入，寫入權限完全由不經 LLM 的程式把關。

## Consequences

- 待確認的提案可以出現在回答中，但必須標為「待確認」，並排在已確認的事實之後。
- Agent 的每一輪在建立提案後結束；確認不會恢復任何 graph 執行狀態，因此不需要 checkpointer 來支撐確認流程。
