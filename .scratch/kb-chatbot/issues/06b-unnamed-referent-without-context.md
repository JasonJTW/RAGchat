# 06b: 沒有上文時，代名詞問題先請使用者說明

**What to build:** 對話的第一題（沒有上文）如果提到沒點名的東西（例如「那它是哪幾年辦的？」），server 不檢索、不作答，固定回「請問你指的是哪個計畫或主題？」。判斷放在程式裡、回答之前：問題含「它／那／這／其」時，用 `CHAT_MODEL` 的 `generateText` 判斷「有／沒有」提到沒點名的東西；判斷和回答同時開始，回答先不送出，判斷為「沒有」才送出回答，為「有」就丟掉回答改送固定句。有上文的追問不判斷，照 06a 改寫。

從原本的 06 拆出，兩次 strike 的紀錄在下方。

**Blocked by:** 06a

**Status:** ready-for-agent

- [ ] 按「新對話」後直接問 Q3（沒有上文），不會回答成大直計畫的年份
- [ ] 同一批文件下，Q2、Q4、Q5、Q9、Q11 第一題照常回答且符合 answer key，沒有被反問；第一個字在送出後 5 秒內出現
- [ ] Q2→Q3 的追問仍符合 answer key（不被反問）
- [ ] server 測試（mock 模型）：沒上文且判斷為「有」時，回固定句且沒有呼叫檢索；判斷為「沒有」或問題不含代名詞時照常回答

## Strikes

- 試過：server 在有對話紀錄時用 `generateText`（`CHAT_MODEL`）把追問改寫成獨立問題再檢索，回答帶著紀錄；前台加「新對話」(`setMessages([])`)。之後在 system prompt 加一條「沒有前文時不要猜『它』指什麼，請使用者說明」。保存在分支 `strike/06-attempt-1`。
- 觀察到：server 測試、「新對話」E2E、live 的 Q2→Q3 追問（回答與出處）都綠；按「新對話」後送出的請求只帶 1 則訊息。但沒有上文直接問 Q3 時，兩次 live 都答成「2008 秋–2012 春、20 多個案例」：檢索單靠「哪幾年辦的、幾個案例」就把大直段落排到前面。
- 診斷結果（HTTP 迴圈，每組 5–8 次）：檢索 6 段裡有 3 段是大直／2008–2012，模型就把「它」當成大直；說明段落不算上文、`reasoningEffort: medium` 都沒用（全紅）。規則放在 system prompt 最前面時會綠，但有上文的追問也有 2/3 次被要求澄清。改成只在沒有上文時（server 知道 `turns.length === 0`）把規則放到 prompt 最前面：沒有上文問 Q3 紅 0/8、有上文的追問 5/5 答對。修正就是 attempt-2 的做法。
- 重試（implementer，套用上面的修正）：server 測試、全套 suite、E2E 都綠；但 live 的一般第一題（Q2、Q4、Q5、Q9、Q11、C1）全被回「請說明你指的是哪個計畫或主題。」。規則放寬時一般問題 10/10 對、沒上文的 Q3 卻有 1/6 又答成大直；加上「有說出主題就不適用」時 Q3 10/10 綠、一般問題又全被反問。診斷時只測了 Q3，沒測一般第一題。
- 新假設：放在 prompt 開頭的規則會套用到整個第一題，強度調不到兩邊都對；「這題要不要先問清楚」要在程式裡判斷，不能只靠回答用的 prompt。保存在分支 `strike/06-attempt-2`。
- 使用者的決定（2026-11-04）：判斷放在程式裡、回答之前，驗收不放寬。對話第一題含「它／那／這／其」時，用 `generateText` 問「有沒有說出要問的對象的名稱」（輸出「有」或「沒有」，附正反例）；判斷和檢索＋回答同時開始，回答先不送出，判斷「沒有」就中止回答、只送「請問你指的是哪個計畫或主題？」且不帶出處，判斷「有」就把暫存的回答送出、照常串流。有上文的追問不判斷。
- 原型驗證（2026-11-04，HTTP 迴圈每組 5 次，全綠）：Q2/Q4/Q5/Q9/Q11 第一題照常回答；「這個 megaweaving.net 平台…」「那個旅梯計畫…」「大量交織這個 FB 社團…」「這個旅梯計畫的起點…」不被反問；「其中哪一年的案例最多？」、沒上文的 Q3、「那這個是誰發起的？」都回固定句且沒出處；Q2→Q3 追問答對。有代名詞的第一題第一個字約 2.1 秒（判斷先跑完再回答時最慢 8.8 秒），反問約 1.2 秒。全套 live 13 個測試 12 綠，Q7（不含代名詞，不經判斷）一次第一個字超過 5 秒，重跑 5/5 綠。
