# 06: 追問與「新對話」

**What to build:** 同一個聊天視窗裡，第二題起，server 先用 `CHAT_MODEL` 的 `generateText` 把「對話紀錄＋新問題」改寫成一句獨立的問題，再拿去檢索；回答時仍帶著對話紀錄。前台有「新對話」按鈕，按下清空畫面和對話 state。聊天紀錄只存在分頁 state，重新整理就消失。

**Blocked by:** 04

**Status:** ready-for-agent

- [ ] 上傳 10 份 md 後，先問 Q2 再接著問 Q3，Q3 的回答與出處符合 answer key
- [ ] 按「新對話」後畫面沒有任何訊息；這時直接問 Q3（沒有上文），不會回答成大直計畫的年份
- [ ] server 測試（mock 模型）：有對話紀錄時，送進檢索的是改寫後的問題，不是原句

## Strikes

- 試過：server 在有對話紀錄時用 `generateText`（`CHAT_MODEL`）把追問改寫成獨立問題再檢索，回答帶著紀錄；前台加「新對話」(`setMessages([])`)。之後在 system prompt 加一條「沒有前文時不要猜『它』指什麼，請使用者說明」。保存在分支 `t3/follow-up-attempt-1`。
- 觀察到：server 測試、「新對話」E2E、live 的 Q2→Q3 追問（回答與出處）都綠；按「新對話」後送出的請求只帶 1 則訊息。但沒有上文直接問 Q3 時，兩次 live 都答成「2008 秋–2012 春、20 多個案例」：檢索單靠「哪幾年辦的、幾個案例」就把大直段落排到前面。
- 診斷結果（HTTP 迴圈，每組 5–8 次）：檢索 6 段裡有 3 段是大直／2008–2012，模型就把「它」當成大直；說明段落不算上文、`reasoningEffort: medium` 都沒用（全紅）。規則放在 system prompt 最前面時會綠，但有上文的追問也有 2/3 次被要求澄清。改成只在沒有上文時（server 知道 `turns.length === 0`）把規則放到 prompt 最前面：沒有上文問 Q3 紅 0/8、有上文的追問 5/5 答對。修正 patch 在 `/tmp/diag-06/fix-on-attempt-1.patch`（套在 attempt-1 上）。
- 重試（implementer，套用上面的修正）：server 測試、全套 suite、E2E 都綠；但 live 的一般第一題（Q2、Q4、Q5、Q9、Q11、C1）全被回「請說明你指的是哪個計畫或主題。」。規則放寬時一般問題 10/10 對、沒上文的 Q3 卻有 1/6 又答成大直；加上「有說出主題就不適用」時 Q3 10/10 綠、一般問題又全被反問。診斷時只測了 Q3，沒測一般第一題。
- 新假設：放在 prompt 開頭的規則會套用到整個第一題，強度調不到兩邊都對；「這題要不要先問清楚」要在程式裡判斷，不能只靠回答用的 prompt。補丁在 `/tmp/diag-06/attempt-2.patch`。
